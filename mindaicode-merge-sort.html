Merge Sort is a completely different strategy: split the problem in half, solve each half, then combine the answers. This is called divide and conquer, and it's what gets Merge Sort down to O(n log n) — dramatically faster than Bubble, Selection, or Insertion Sort on large data.

🎓 Real-life example: Split a class of students into two groups, then split those into two more, and so on, until every group has just one student (a group of one is automatically "sorted"). Now merge pairs of groups back together: two teachers each hold a sorted line, and repeatedly let whichever line has the shorter person at the front step forward. Keep merging bigger and bigger groups until the whole class is one sorted line.

def merge_sort(arr, lo, hi):
if hi - lo <= 1:
return
mid = (lo + hi) // 2
merge_sort(arr, lo, mid)
merge_sort(arr, mid, hi)
merge(arr, lo, mid, hi)
 
def merge(arr, lo, mid, hi):
left, right = arr[lo:mid], arr[mid:hi]
i = j = 0; k = lo
while i < len(left) and j < len(right):
if left[i] <= right[j]:
arr[k] = left[i]; i += 1
else:
arr[k] = right[j]; j += 1
k += 1
# copy any leftovers!
arr[k:k+len(left)-i] = left[i:]
arr[k:k+len(right)-j] = right[j:]
void mergeSort(int[] arr, int lo, int hi) {
if (hi - lo <= 1) return;
int mid = (lo + hi) / 2;
mergeSort(arr, lo, mid);
mergeSort(arr, mid, hi);
merge(arr, lo, mid, hi);
}

📚 How it works

Split the array in half, recursively, down to single elements (always sorted). Then merge pairs of sorted halves by always taking whichever front value is smaller. The blue bracket shows the current range being split or merged. Merging is only correct because both halves are ALREADY sorted before it starts.

🧠 Quick check

⚠️ Common mistakes

Forgetting the leftover copy. Once one side runs out, the OTHER side still has values waiting — skip copying them and those values are silently dropped from the result.
Merging unsorted halves. The merge step only works because both halves are already individually sorted. Skip the recursive sort and merge produces garbage.
Using < instead of <= for the tie-break. This flips which side wins on equal values, which can make the sort unstable.
Missing the base case. Without if hi - lo <= 1: return, the recursion never terminates.

On nearly-sorted data — the one case where a "worse" Big-O algorithm can actually win.
