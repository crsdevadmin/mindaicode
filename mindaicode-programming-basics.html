Why can't I just write x = y and y = x?
Because the first line already overwrote x. The moment x = y runs, the 5 that was in x is gone — permanently. So y = x copies 10 back. You end up with two 10s and no 5.
Is the two-variable version better because it uses less memory?
Almost never. A temp variable costs one CPU register, which is nothing, and compilers optimise the temp swap perfectly. The arithmetic and XOR versions are interview curiosities — they are usually slower and they have real failure cases you can try at Intermediate and Pro level.

Why on earth does counting start at 0?
An index is really a distance, not a position. Index 0 means "0 boxes away from the start" — the first box. Index 3 means "3 boxes along." Read it as distance and it stops feeling weird.
What happens if I ask for a box that doesn't exist?
The program crashes with an "index out of range" error. With 5 boxes the valid indexes are 0 to 4. There is no index 5 — one of the most common bugs in all of programming.

Why does range(5) run 5 times but never reach 5?
Because it starts at 0. It gives 0, 1, 2, 3, 4 — count them, that is five values. It stops before 5, exactly like array indexes.
Does the loop variable have to be called i?
No. i is just an old habit that stuck (it stands for "index"). You will see i, j and k everywhere, including on the rest of this site.

What is % actually doing?
It divides and hands back only the remainder. 7 % 2 is 1, because 7 divided by 2 is 3 with 1 left over. So "n % 2 == 0" asks "does 2 divide into n cleanly?"
What is the difference between return and printing?
Printing shows a value on screen for a human. Returning hands it back to whatever called the function so the program can keep using it. A function that prints but never returns gives the rest of your code nothing.
Why is = sometimes ==?
One = means "put this value in that box". Two == asks a yes/no question: "is x equal to 5?" It changes nothing. Mixing them up is a classic beginner bug.

THERE ARE NO DUMB QUESTIONS
What is the "base case"?
It is the person in row 1 — the one who can answer without asking anyone else. In code it is the if at the top. It is what stops the chain.
What if there is no base case?
The asking never stops. Every call waits on the next, forever, and the program runs out of memory. That crash has a name you will hear a lot: stack overflow.
Why does the last call finish first?
Because the work sits after the recursive call. Nothing can finish until the one it is waiting on finishes. You will meet this exact shape again in Module 3 — it is called a stack.
