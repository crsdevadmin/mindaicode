🌀 Recursion & Dynamic Programming

Plain recursion can recompute the exact same sub-problem thousands of times without noticing. Dynamic programming is just recursion with a notebook — remember an answer once, and reuse it instead of recalculating it. That single idea turns exponential blowups into fast, linear-or-better solutions.

Module 7 · Three classic examples below: Fibonacci (the simplest case), 0/1 Knapsack, and Longest Common Subsequence.

🌀 Fibonacci: Naive vs Memoized not earned

Naive recursion recomputes fib(k) from scratch every single time it's needed. Memoization computes it once, writes it in a notebook, and just looks it up next time.

# dp[i][c] = best value using the first i items with capacity c
for i in range(1, n+1):
for c in range(capacity+1):
if weight[i-1] > c:
dp[i][c] = dp[i-1][c] # item doesn't fit, skip it
else:
dp[i][c] = max(dp[i-1][c],
dp[i-1][c-weight[i-1]] + value[i-1])
int[][] dp = new int[n + 1][capacity + 1];
for (int i = 1; i <= n; i++) {
for (int c = 0; c <= capacity; c++) {
if (weight[i-1] > c) {
dp[i][c] = dp[i-1][c]; // item doesn't fit, skip it
} else {
dp[i][c] = Math.max(dp[i-1][c],
dp[i-1][c-weight[i-1]] + value[i-1]);
}
}

Every DP solution follows the same recipe: define what a "sub-problem" means, write a rule for combining smaller sub-problems into bigger ones, then fill a table (or a memo) so no sub-problem is ever solved twice.
