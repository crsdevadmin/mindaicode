🔐 Hash Tables: Chaining vs Open Addressing

A hash table is a row of numbered lockers. A hash function turns any key into a locker number in O(1) — no searching required. The interesting part is what happens when two different keys hash to the same locker. That's a collision, and there are two classic ways to handle it.

Module 4 · Every key you type below is inserted into both structures at once, so you can watch them handle the exact same collision differently.

for (char c : key.toCharArray()) sum += c;
return sum % n;

📈 Chaining vs Open Addressing

PropertySeparate ChainingOpen Addressing
What lives in a slotA list of every key that hashed thereAt most one key
Can the table ever be "full"?No — lists just growYes — capped at table size
On a collisionAppend to that slot's listProbe forward to the next open slot
Deleting a keyRemove it from the listMust leave a tombstone, not an empty slot
Average lookup timeO(1) if load factor stays lowO(1) if load factor stays low

That tombstone rule is the part everyone forgets: if deleting simply cleared a slot to empty, a later search could stop early at that empty slot and wrongly report "not found" for a key that actually probed past it and landed further along.
