Heap Sort arranges values into a binary tree shape (stored in a plain array!) where every parent is greater than or equal to its children — called a max-heap. The largest value always ends up at the very top. Pull it off, put the last leaf in its place, let it "sink" back down to restore the shape, and repeat.

🎓 Real-life example: Arrange students into a pyramid photo formation where everyone must be at least as tall as the two people standing below them — the tallest student ends up at the very top. Send that top student to the back of the sorted line, move the last student in the pyramid up to fill the gap, and let them "sink" downward by swapping with whichever child is taller, until the height order is valid again. Repeat until the pyramid is empty.

💻 The Code

def heap_sort(arr):
n = len(arr)
for i in range(n // 2 - 1, -1, -1):
sift_down(arr, n, i)
for end in range(n - 1, 0, -1):
arr[0], arr[end] = arr[end], arr[0]
sift_down(arr, end, 0)
 
def sift_down(arr, size, i):
while True:
largest = i
l, r = 2*i+1, 2*i+2
if l < size and arr[l] > arr[largest]: largest = l
if r < size and arr[r] > arr[largest]: largest = r
if largest == i: break
arr[i], arr[largest] = arr[largest], arr[i]
i = largest
void heapSort(int[] arr) {
int n = arr.length;
for (int i = n/2 - 1; i >= 0; i--)
siftDown(arr, n, i);
for (int end = n - 1; end > 0; end--) {
swap(arr, 0, end);
siftDown(arr, end, 0);
}
}
 
void siftDown(int[] arr, int size, int i) {
while (true) {
int largest = i;
int l = 2*i+1, r = 2*i+2;
if (l < size && arr[l] > arr[largest]) largest = l;
if (r < size && arr[r] > arr[largest]) largest = r;
if (largest == i) break;
swap(arr, i, largest);
i = largest;
}
}

📚 How it works

A binary heap stored in an array uses simple index math: for node i, its children live at 2i+1 and 2i+2. No pointers needed! Heap Sort builds a max-heap in O(n), then extracts the max n times, each costing O(log n) — giving a guaranteed O(n log n) with no bad-input worst case.
Worst: O(n log n) Average: O(n log n) Best: O(n log n) Stable: No Space: O(1)

🧠 Quick check

⚠️ Common mistakes

Only checking one child. Sift-down must compare BOTH children to find the true largest — checking only the left child misses cases where the right child is bigger.
Forgetting to shrink the heap size. After each extraction, already-sorted values at the end must be excluded from future sift-downs, or they get pulled back in and corrupt the result.
Off-by-one in child index formulas. Children of index i are at 2i+1 and 2i+2 — easy to mix up with 1-indexed heap formulas from textbooks.
Building the heap from the wrong index. Start from the last non-leaf parent (n//2 - 1), not from a leaf or from index 0.
