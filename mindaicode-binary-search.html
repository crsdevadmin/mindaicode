🔍 Why did we bother sorting?

Here's the payoff. Once a list is sorted, you can find anything in it almost instantly. There's more than one way to take advantage of that — three, in fact, each throwing away a different amount of work. On a sorted list of a million items, binary search finds any value in 20 steps, jump search takes about 1,000, and checking one by one would take up to a million.

🎓 Real-life example: Looking for "Priya" in a class register. Linear search is reading every name from the top until you hit hers. Jump search is flipping ahead in fixed chunks — page 1, page 2, page 3 — until you overshoot her page, then reading that one page carefully. Binary search is what you actually do with a sorted register — open the middle, see you're at "M", and instantly ignore the entire first half. Repeat. That's it.

All three only work on sorted data — which is exactly what the six sorting algorithms were for.

Linear vs Jump vs Binary Search 🔍

All three search the same sorted list for the same target, at the same time. Watch how much work each one does.

🐌 Linear SearchO(n)
Checks 0 item(s) · ready
Starts at the first item and walks forward one at a time.
🦘 Jump SearchO(√n)
Checks 0 item(s) · ready
Hops forward in fixed blocks, then walks back through the one block it lands in.
⚡ Binary SearchO(log n)
Checks 0 item(s) · ready
Jumps to the middle and throws away half the list each time.

💻 The Code

def binary_search(arr, target):
lo, hi = 0, len(arr) - 1
while lo <= hi:
mid = (lo + hi) // 2
if arr[mid] == target:
return mid # found it
elif arr[mid] < target:
lo = mid + 1 # throw away left half
else:
hi = mid - 1 # throw away right half
return -1 # not in the list
int binarySearch(int[] arr, int target) {
int lo = 0, hi = arr.length - 1;
while (lo <= hi) {
int mid = lo + (hi - lo) / 2;
if (arr[mid] == target) return mid;
else if (arr[mid] < target) lo = mid + 1;
else hi = mid - 1;
}
return -1;
}
⚠️ Watch out: in Java, writing (lo + hi) / 2 can overflow when the array is huge, which is why the code above uses lo + (hi - lo) / 2. This exact bug sat undetected in Java's own library for nine years.

📈 Why "throw away half" is so powerful

Worst-case number of items each method has to look at.

List size🐌 Linear O(n)🦘 Jump O(√n)⚡ Binary O(log n)Binary vs Linear

Every time the list doubles, binary search needs just one extra step — that is what O(log n) means. Jump search sits in the middle: its steps grow with √n, so a list 100× bigger only needs about 10× more checks. Both beat linear search by throwing away large chunks of the list without checking them one by one.
