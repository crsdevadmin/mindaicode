🗺️ Graphs: BFS, DFS & Dijkstra

Cities connected by roads. BFS floods outward one ring at a time, like water finding every room the same distance away before moving further. DFS is a person exploring a maze — all the way down one corridor before backtracking. Dijkstra asks a sharper question: not "how many roads?" but "what's the cheapest total distance?"

🌊 Breadth-First Search not earned

This is how a maps app finds a route. BFS spreads outwards from where you are — everything 1 stop away, then everything 2 stops away, then 3 — until it reaches your destination. The first time it arrives, it has arrived by the fewest stops. Whether that is the fastest journey is a different question, and the demo will show you why.

🗺️ How does Google Maps actually do this?

1. What you just watched

Type a destination into a maps app and it does not somehow "know" the route. It searches — and the search looks a lot like what just happened on the map above.

The road network is a graph: junctions are nodes, roads are edges. Your search starts at one node and spreads outwards until it touches the destination.

2. Why BFS spreads in rings

BFS uses a queue — first in, first out. Stations discovered earlier come out earlier, so everything 1 stop away is processed before anything 2 stops away.

That ordering is the whole trick. Because the search never reaches distance 3 before finishing distance 2, the first time it touches your destination it must have arrived by the fewest possible stops. You get the shortest route for free, just from the order of the queue.

Swap the queue for a stack and you get DFS, which dives down one road to the end of the map before trying the second road out of your own street. Same graph, same cost, useless for directions.

3. The bit that catches everyone out

BFS counts stops. It never looks at the numbers written on the lines.

On the starting map, Chennai Central to Airport is 4 stops via Egmore and Guindy — and BFS is perfectly correct that this is the fewest stops possible. It also takes 35 minutes, because that Egmore–Guindy line is a slow 22-minute crawl.

Go one extra stop through Vadapalani and you arrive in 28 minutes. Fewer stops, slower journey. If a maps app worked this way it would confidently route you into the traffic.

4. So Maps uses Dijkstra, not BFS

Dijkstra is BFS with the queue upgraded: instead of "who was discovered first", it always expands whoever is closest so far, using a priority queue. Now the numbers on the edges matter, and "closest" can mean minutes, kilometres, fuel, or toll cost — whatever you put on the edges.

That is the Dijkstra demo further down this page, running on this same map. Compare the two and you are comparing "fewest stops" against "least time".

5. Where BFS is the right answer

Whenever every step genuinely costs the same, BFS is not just adequate — it is the better choice, because it is simpler and needs no priority queue:

  • Metro route planners minimising interchanges, where a change of line costs you more than a stop
  • "Degrees of separation" — how many friend-hops between two people on a social network
  • Shortest path in a maze or grid, where every move to an adjacent square costs one
  • Web crawlers exploring pages near a starting site first
  • Chess puzzles — fewest moves to reach a position

6. Being honest about the real thing

A real maps app is a long way beyond plain Dijkstra. Running Dijkstra across every road in India for every request would be far too slow, so production routing engines add:

  • A* — Dijkstra plus a hint about which direction the destination lies in, so it stops exploring backwards
  • Contraction hierarchies — the road network is pre-processed for weeks so motorway-level shortcuts can be reused instantly
  • Live traffic — edge weights change minute by minute from other people's phones
  • Turn costs — a left turn across traffic genuinely costs more than a right one

But every one of those is a modification of the idea you just watched: spread out from the start, keep track of what you have already seen, stop when you arrive. Understand BFS and Dijkstra and you understand the shape of all of it.

from collections import deque
def bfs(graph, start):
visited = {start}
queue = deque([start])
order = []
while queue:
node = queue.popleft() # FIFO — oldest discovered first
order.append(node)
for neighbor, _ in graph[node]:
if neighbor not in visited:
visited.add(neighbor)
queue.append(neighbor)
return order
Queue<String> queue = new LinkedList<>();
Set<String> visited = new HashSet<>();
queue.add(start); visited.add(start);
while (!queue.isEmpty()) {
String node = queue.poll();
for (String next : graph.get(node))
if (visited.add(next)) queue.add(next);
}

🧭 Depth-First Search not earned

Follows one road as far as it possibly can before backtracking — like a person in a maze taking corridors one at a time until they hit a dead end.

def dfs(graph, node, visited=None, order=None):
if visited is None: visited, order = set(), []
visited.add(node)
order.append(node)
for neighbor, _ in graph[node]:
if neighbor not in visited:
dfs(graph, neighbor, visited, order) # go deep first
return order
void dfs(String node, Set<String> visited) {
if (!visited.add(node)) return;
order.add(node);
for (String next : graph.get(node)) dfs(next, visited);
}

🚚 Dijkstra's Shortest Path not earned

Always settles the closest un-settled city next. Guarantees the cheapest total distance, even if that route uses more roads than a "shorter-looking" one.

def dijkstra(graph, start):
dist = {node: float('inf') for node in graph}
dist[start] = 0; settled = set()
while len(settled) < len(graph):
node = min((n for n in graph if n not in settled), key=lambda n: dist[n])
settled.add(node) # closest unsettled city, finalized
for neighbor, weight in graph[node]:
if dist[node] + weight < dist[neighbor]:
dist[neighbor] = dist[node] + weight # relax the edge
return dist
PriorityQueue<Node> pq = new PriorityQueue<>(Comparator.comparingInt(n -> n.dist));
dist.put(start, 0); pq.add(new Node(start, 0));
while (!pq.isEmpty()) {
Node cur = pq.poll();
if (settled.contains(cur.id)) continue;
settled.add(cur.id);
// relax every neighbor edge, push improvements onto pq
}
⚠️ Watch out: Dijkstra assumes every road weight is zero or positive. A negative weight can make the algorithm settle a station too early and never revisit it — for graphs with negative edges, use Bellman-Ford instead.
