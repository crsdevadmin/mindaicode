Quick Sort picks one value as a pivot, then rearranges everything else around it: smaller values to the left, larger values to the right. Once that's done, the pivot is sitting in its exact final position — forever. Then it repeats the same trick on the left and right groups.

🎓 Real-life example: Pick one student in the class as a reference height. Ask everyone to shuffle around: shorter students step to the left, taller students step to the right. The reference student never has to move again — they're now standing exactly where they belong in the final sorted line. Repeat the same trick separately on the "shorter" group and the "taller" group.

💻 The Code

def quick_sort(arr, lo, hi):
if lo >= hi:
return
p = partition(arr, lo, hi)
quick_sort(arr, lo, p - 1)
quick_sort(arr, p + 1, hi)
 
def partition(arr, lo, hi):
pivot = arr[hi]
i = lo - 1
for j in range(lo, hi):
if arr[j] <= pivot:
i += 1
arr[i], arr[j] = arr[j], arr[i]
arr[i+1], arr[hi] = arr[hi], arr[i+1]
return i + 1
void quickSort(int[] arr, int lo, int hi) {
if (lo >= hi) return;
int p = partition(arr, lo, hi);
quickSort(arr, lo, p - 1);
quickSort(arr, p + 1, hi);
}
 
int partition(int[] arr, int lo, int hi) {
int pivot = arr[hi];
int i = lo - 1;
for (int j = lo; j < hi; j++) {
if (arr[j] <= pivot) {
i++;
swap(arr, i, j);
}
}
swap(arr, i + 1, hi);
return i + 1;
}

📚 How it works

Every partition places its pivot in its final sorted position immediately — unlike Merge Sort, where nothing is truly final until the very last merge. Quick Sort sorts in place (no extra array), which is why it's often faster in practice than Merge Sort despite matching Big-O on average.
Average: O(n log n) Worst: O(n²) Best: O(n log n) Stable: No Space: O(log n)

🧠 Quick check

⚠️ Common mistakes

Forgetting to place the pivot. After partitioning, the pivot MUST be swapped into position i+1 — skip this and it never lands in its correct final spot.
Comparing against an inconsistent value. Every comparison in one partition call must use the SAME pivot value, or the partition boundary becomes meaningless.
Always picking the first or last element as pivot. On already-sorted (or reverse-sorted) data, this creates maximally unbalanced partitions — the O(n²) worst case.
Forgetting the pivot's own index is excluded from both recursive calls (p-1 and p+1) — it's already in its final place and never needs revisiting.

⚡ The Race: Quick Sort vs Merge Sort

On already-sorted data — the exact case that exposes Quick Sort's O(n²) worst case with this pivot strategy.
