Selection Sort works completely differently from Bubble Sort. Instead of swapping neighbours as it goes, it does one thing at a time: scan the entire remaining list for the smallest value, then place it — once.

🎓 Real-life example: A teacher looks at a whole group of unsorted students and, without moving anyone yet, scans everyone to find the shortest student — remembering who that is as she goes. Once she's checked everyone, she brings THAT ONE student to the front of the line. Then she repeats with the remaining group. Only one student moves per round — very different from Bubble Sort's constant neighbour-swapping.

💻 The Code

def selection_sort(arr):
n = len(arr)
for i in range(n):
min_idx = i
for j in range(i + 1, n):
if arr[j] < arr[min_idx]:
min_idx = j
arr[i], arr[min_idx] = arr[min_idx], arr[i]
return arr

📚 How it works

For each position i, scan the ENTIRE remaining unsorted part to find the index of the smallest value (min_idx). Only after the scan finishes do we swap it into position i — one swap per pass, maximum. The sorted region grows from the left this time (opposite of Bubble Sort, which grows from the right).
Worst: O(n²) Average: O(n²) Best: O(n²) Swaps: O(n) max Space: O(1)

🧠 Quick check

⚠️ Common mistakes

Swapping during the scan. A common bug is swapping arr[j] and arr[min_idx] the moment a smaller value is found. That's wrong — Selection Sort only tracks the index (min_idx = j) while scanning, and swaps ONCE after the whole scan finishes.
Wrong comparison direction. Using arr[j] > arr[min_idx] instead of < finds the MAXIMUM instead of the minimum — the array still changes, just not correctly.
Expecting a best-case shortcut. Unlike Bubble Sort, there's no early exit here — Selection Sort always scans the full remaining array on every pass, even if the input is already sorted. Best case is still O(n²).
Assuming it's stable. Standard Selection Sort is not stable — swapping the minimum into position i can jump it past other equal-valued elements, changing their original relative order.
