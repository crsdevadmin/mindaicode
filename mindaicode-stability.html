⚖️ What "stable" actually means

Every textbook table has a Stable: Yes/No column, and almost nobody explains what it costs you. Here it is in one screen.

A sort is stable if items with equal values keep the order they were already in. It only matters when you sort the same data twice, by two different things — which is exactly what real applications do all the time.

🃏 Insertion Sort — stable

Only shifts values; never jumps them past each other

🔎 Selection Sort — not stable

Swaps distant values, which can leapfrog equal ones

💡 Why it happened

Where this bites in real life: an online shop sorts products by rating, then the user sorts by price. With a stable sort, items at the same price stay in rating order — the earlier sort still counts. With an unstable sort, that earlier work is scrambled and the list looks random to the user.

This is why Java uses a merge-sort variant for objects, and why Python's sorted() is guaranteed stable — so you can sort by one key, then another, and both hold.

Notice the pattern: the sorts that only move things one step at a time tend to be stable. The fast ones that fling values across the array are not — that speed is exactly what costs them stability.
