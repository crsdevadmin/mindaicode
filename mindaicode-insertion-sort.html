Insertion Sort works like sorting a hand of playing cards. You pick up the next card, and slide it left past any bigger cards already in your hand until it lands in the right spot.

🎓 Real-life example: A teacher already has a neat line of students sorted by height. A new student walks up. The teacher holds that student out of the line, and shifts the taller students in the line one step to the right — one at a time — until she finds the gap where the new student fits. Then she places them in that gap. The line stays sorted the whole time; only ONE person is ever "outside" it.

💻 The Code

def insertion_sort(arr):
n = len(arr)
for i in range(1, n):
key = arr[i]
j = i - 1
while j >= 0 and arr[j] > key:
arr[j + 1] = arr[j]
j -= 1
arr[j + 1] = key
return arr

int n = arr.length;

int j = i - 1;
while (j >= 0 && arr[j] > key) {
arr[j + 1] = arr[j];
j--;

📚 How it works

For each position i, hold onto key = arr[i]. Slide every value bigger than key one step right, opening a gap. Drop key into that gap. The sorted region (green) is always everything to the left of i, and it grows one element at a time.
Best: O(n) Average: O(n²) Worst: O(n²) Stable: Yes Space: O(1)

🧠 Quick check

⚠️ Common mistakes

Missing the j >= 0 check. If you only check arr[j] > key, once j goes negative you'll read arr[-1] — a crash in Java, silently wrong in Python (which wraps negative indices!).
Forgetting to decrement j. Skip j -= 1 and the while loop never ends — an infinite loop.
Forgetting the final placement. arr[j + 1] = key after the loop is what actually drops the key into its gap — skip it and the key's value is lost.
Assuming it needs a scan like Selection Sort. It doesn't — it only looks LEFT from position i until it finds a value ≤ key or hits the start. No global minimum search.
